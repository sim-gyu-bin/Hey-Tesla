# Hey Tesla UI

이 저장소 전용 스킬이다. 전역 UI 규칙이나 Tesla 공식 디자인 시스템이 아니다. **사용자는 현재 상태와 다음 행동을 보고, 개발자는 진단 화면에서 근거를 확인한다.** 앱을 Wiki 뷰어로 만들지 않는다.

## 적용과 작업 순서

1. 요청이 검토인지 구현인지 먼저 구분한다. 검토 요청에는 앱 코드를 바꾸지 않는다. 구현 요청에는 실제로 동작하는 범위를 완결하며 장식용 버튼·가짜 수치를 넣지 않는다.
2. 대상 화면의 기존 Compose 코드와 상태·콜백을 읽는다. 기존 테마·컴포넌트가 생겼다면 재사용한다. 두 번째 테마/상태 머신을 만들지 않는다.
3. 필요한 맥락만 읽는다: [UI 검토와 단계별 개편](../../../wiki/UI-Design.md), 안전 동작 변경 시 [요구사항](../../../wiki/Requirements.md)·[상태 머신](../../../wiki/State-Machine.md). 과거 실측 수치를 최신 동작으로 추정하지 않는다.
4. 화면마다 **목적, 실제 상태 출처, 주 행동 하나, 막힘/진행/오류/미구현 표현, 기존 기능의 이동 위치**를 정한다. 신규 데이터가 필요한 표현은 구현된 상태 출처 없이는 추가하지 않는다.
5. Kotlin·Compose·기존 Material 3 기반으로 구현한다. UI 작업에 React Native·WebView·HTML 화면·별도 차량 SDK·새 음성 엔진을 끼워 넣지 않는다.
6. 실제 화면과 수명주기를 검증하고 Wiki에 구현 범위·근거·남은 제한을 갱신한다. UI 구현 완료를 음성 엔진·실차 기능 완료로 보고하지 않는다.

- 설정 행은 `아이콘 + 제목 + 현재 상태/짧은 설명 + 진입 표시` 패턴으로 통일한다. 기능이 없는 행을 미래 메뉴로 미리 채우지 않는다.
- 운영 목표는 초기 설정 후 잠금·주머니 무터치다. 매번 홈을 열거나 마이크/프렁크 버튼을 누르는 흐름을 필수 사용법으로 설계하지 않는다.

### 화면 구성 계약

색상 변경이나 차량 그림 추가만으로 문서형 UI가 해결됐다고 판단하지 않는다. **스크롤은 허용하되 읽기 순서는 대상 → 상태 → 행동 → 상세**로 고정한다.

| 화면 | 기본 배치 | 상세 정보 처리 |
| --- | --- | --- |
| 홈 | 상단 앱명·설정 → 차량 식별과 여백 → 핵심 상태 → 주 행동 하나 | 준비 항목은 보조 정보로 낮추고 시험 절차·원시 결과는 넣지 않는다 |
| 설정 | 상단 제목·뒤로 → 목적별 메뉴 행 → 개발자 진단 진입 | 권한별 설명을 처음부터 펼치지 않는다. 필요한 경고는 실행할 행/버튼 근처에서 제공한다 |
| 개발자 진단 | 진단 종류 → 입력 선택 → 실행/중지 → 짧은 결과 | 기술 메타데이터·로그·해제 근거는 명시적인 상세 펼치기로 제공한다 |

- 잘못된 예: `긴 제약 설명 → 권한 true/false → 같은 채움 버튼 여러 개 → 시험 절차 → 로그`. 좋은 예: `차량 등록 필요 → 차량 등록하기`, 기술 근거는 설정의 진단 목적지에서 확인한다.
- 모든 섹션을 같은 카드로 감싸지 않는다. 여백·타이포·구분선으로 충분한 곳에는 배경 박스를 추가하지 않는다. 홈의 주 행동과 설정 진입이 서로 경쟁하지 않게 한다.
- 제목은 짧게, 보조 설명은 한 가지 사실만 전달한다. 상세 접기는 설명량을 줄이는 도구이지 실패·진행·중지·안전 경고를 감추는 도구가 아니다.
- 좁은 화면과 큰 글자에서는 가로 버튼 묶음을 줄바꿈하거나 세로로 배치한다. 진단 종류는 가로 스크롤/적응형 배치로 모두 접근 가능하게 한다. 글자 축소·고정 높이·말줄임으로 주요 상태를 숨기지 않는다.
- 홈의 중심 영역은 실데이터 기반 차량명·상태만으로도 성립해야 한다. 허가된 에셋이 없다고 장식용 계기판·가짜 차량 렌더·샘플 수치를 만들지 않는다.
- 개편 전에 **설치 버전과 소스 버전**을 비교한다. 앱 버전 표시는 `BuildConfig.VERSION_NAME`·`VERSION_CODE`만 사용하고 하드코딩하지 않는다. 소스의 빌드 55를 v54 설치 표시 이력에 덮어쓰거나 호스트 smoke를 v55 실기기 성공으로 확대하지 않는다. 저장소에 새 UI가 있어도 기기에 구형 APK가 남아 있을 수 있으므로 설치·실제 화면 관측과 소스 구현을 구분한다.


## 상태와 행동의 정직성

화면 상태는 기존 런타임 값에서 도출한다. 색상이나 문구를 위해 별도의 성공 상태를 저장하지 않는다.

| 관측 | 허용 표현 | 금지 표현 |
| --- | --- | --- |
| 차량 association 없음 | 차량 등록 필요 | 차량 연결됨 |
| association만 있음 | 차량 등록됨 | 근처에 있음·차량 제어 가능 |
| 실제 BLE 출현만 있음 | 근접 신호 확인 | 사용자 인증 완료·프렁크 실행 가능 |
| `ko-KR` 지원 보고 | 한국어 모델 설치 확인 | 음성 리모컨 준비 완료 |
| TTS 파일 문장 일치·신뢰도 0.0 | 시험 문장 일치 / 신뢰도 기준 미충족 | 안전한 명령 인식 성공 |
| PCM/TTS 파일 처리 | 파일 인식 중 | 마이크 녹음 중 |
| 제한 마이크 진단 | 마이크 진단 중 | 호출어 대기 중 |
| 차량 제어 미구현 | 차량 제어 미연결 | 프렁크 열기 버튼의 가짜 성공 |
| 명령을 전송했으나 완료 미관측 | 요청 전송 / 결과 확인 안 됨 | 열렸어요 |

- 진행 중인 입력에는 중지/취소를 찾기 쉽게 둔다. 정리 실패·재시작 필요는 일반 성공 상태보다 우선한다. 다른 기능으로 이동해 문제를 감추지 않는다.
- 실제 입력 없음·미지원·낮은 신뢰도·오래된 차량 상태·`UNKNOWN`을 빈 화면이나 초록색 완료로 바꾸지 않는다.
- 배터리, 위치, 기어 P, 잠금, 프렁크 열림 상태를 꾸미기 위해 샘플 값으로 채우지 않는다. 없는 데이터는 생략하거나 해당 맥락에 `확인 안 됨`으로 표시한다.
- 현재 앱의 TTS 입력은 시험 도구이지 호출어 인증이나 차량 권한의 증거가 아니다.

## 시각 방향과 토큰

Tesla 공개 화면에서 참고할 것은 **대상 중심의 큰 시각 요소, 넓은 여백, 짧은 상태, 저채도 배경, 직접 조작과 상세 메뉴의 분리**다. 아래 값은 Tesla에서 추출한 수치가 아니라 이 프로젝트의 초기 제안이다. 현재 도입한 색상·타이포의 단일 원본은 `app/src/main/java/com/heytesla/app/ui/AppTheme.kt`이며 공통 표현은 같은 디렉터리의 `AppComponents.kt`를 재사용한다.

| 토큰 | 초기 값 | 용도 |
| --- | --- | --- |
| Background | `#17181A` | 차콜 기본 배경 |
| Surface | `#222427` | 필요한 상태 묶음·입력 영역만 |
| Text | `#F4F4F5` | 제목·주요 본문 |
| Secondary | `#B5B8BE` | 보조 상태·설명 |
| Accent | `#84B6FF` | 진행·선택·링크 |
| Success | `#74D9A0` | 실제로 확인된 완료에만 |
| Warning | `#EDC477` | 준비 필요·주의 |
| Error | `#FF8A8A` | 실패·중단 필요 |

- 다크를 초기 방향으로 삼되, 기존에 구현된 사용자 테마 선택은 유지한다. 라이트·동적 색상을 추가할 때는 동일한 상태 의미와 대비를 다시 검증한다.
- 주요 CTA는 밝은 중립 배경과 어두운 글자, 보조 행동은 행/텍스트/아웃라인으로 구별한다. 화면 전체를 같은 채움 버튼이나 카드로 만들지 않는다.
- 위 6개 전경색과 두 배경의 불투명 조합은 WCAG 문자 대비 6.86:1 이상으로 계산됐다. 투명도·오버레이·비활성 상태·다른 배경에는 이 수치를 재사용하지 않는다. 색상만으로 상태를 구별하지 않는다.
- 간격: `4 / 8 / 12 / 16 / 24 / 32 / 48 dp`. 기본 좌우 여백 24dp, 좁은 화면은 16dp. 관련 항목 8~12dp, 섹션 24~32dp. 큰 제목 28~32sp, 섹션 20~22sp, 본문 16sp, 보조 14sp를 출발점으로 삼는다.
- 모서리는 12~16dp 범위의 적은 종류로 제한한다. 과도한 알약·유리 효과·그라데이션·섀도·장식용 카드 중첩은 사용하지 않는다.
- Android 시스템 한국어 글꼴을 우선한다. Tesla 전용 글꼴·T 로고·공식 앱 아이콘·스크린샷·3D 렌더링을 앱 에셋으로 복사하지 않는다.
- 차량 시각 요소는 적법한 자체/허가 에셋으로 만들고 상태 이해를 돕는 경우에만 쓴다. 에셋이 없으면 실제 차량명/등록 상태를 잘 배치한다. 무거운 3D 엔진이나 가짜 차량 상태를 추가하지 않는다.
- 우리 앱은 Hey Tesla로 명확히 식별한다. 충전·공조·Summon·지도·Powerwall은 이 제품의 기능 범위가 아니다.

## 문구와 설명 밀도

- 홈은 상태와 다음 행동이 먼저다. 긴 기술 설명은 진단 상세 또는 Wiki로 옮긴다. `1. 권한 ... 2. association ...` 같은 시험 절차를 홈 구조로 사용하지 않는다.
- `마이크: true` → `마이크 권한 허용됨`, `association 없음` → `차량 등록 필요`처럼 사용자 언어로 번역한다. 코드와 계측값은 진단에서 그대로 확인 가능해야 한다.
- `지원 확인`, `문장 일치`, `명령 전송`, `차량 승인`, `물리 완료`는 서로 다른 결과다. 모두 `성공`으로 합치지 않는다.
- 기본 비서 대체·권한 요청·차량 조작의 주의사항은 해당 행동 가까이에 둔다. 첫 화면에서 문단을 줄인다는 이유로 승인 직전 경고까지 없애지 않는다.
- 인식 원문은 일반 로그에 저장하지 않는다. 실차 시험의 기존 마스킹 순환 로그는 유지한다. 사용자가 직접 시작한 개발용 마이크 음성 시험은 녹음·최종 인식 원문을 기본으로 앱 내부 백업 제외 전용 저장소에 보관한다. 별도 저장 동의 체크는 두지 않고 시작 버튼 가까이 기본 저장을 안내한다. 화면 진입·복원·복귀만으로 녹음하지 않으며 실차 안전 동의는 유지한다. 합성·무음 파일·부분 인식의 자동 저장·자동 업로드·백업·자동 삭제는 금지한다. ADB 회수물은 Git 제외 영역에만 보관한다. 저장 녹음 재시험은 마이크·차량 명령 경로와 분리한다. 개인정보·VIN·토큰은 기존처럼 일반 로그·Wiki·저장소에 기록하지 않는다.
- v0.51부터 사용자가 직접 시작한 일반 음성 시험·실차 음성 시험의 n-best 원문은 결과 상세에 최대 3개 후보와 점수, 전체 후보 수, 실차 시험의 판정·차단 사유와 함께 표시한다. 이 표시 상태는 RAM에만 두고 다음 같은 시험 시작·앱 프로세스 종료 시 지운다. 일반 로그·RAM 이벤트·시험 요약·필드 스냅샷·새 파일로 내보내지 않는다. 사용자 취소 회차는 표시하지 않는다. 주변 대화도 표시될 수 있음을 함께 안내하고 문장 인정도 `차량 실행 허가 아님`으로 표시한다.
- v0.52의 sherpa-onnx 그림자 인식 원문(음성 인식 진단 전용)도 위 n-best와 같은 RAM 전용·취소 회차 미표시·로그/이벤트/요약/파일 미기록 규칙을 따르고, "차량 제어·명령 판정에 사용 안 함"을 함께 표시한다.

## Compose와 수명주기 계약

- 표현용 Composable은 상태와 이벤트를 받는다. 상태 조회·서비스 시작·권한 요청·음성 인식을 composition 부수효과로 발생시키지 않는다.
- 기존 런타임의 권한·화면 표시·오디오 예약·접근 OFF·단일 세션 게이트를 재사용한다. 버튼 비활성화만으로 안전 검사를 대체하지 않는다.
- 현재 `MainActivity`의 `onPause`/`onDestroy`에 있는 지원 조회·STT 취소를 보존한다. **같은 Activity 안의 진단 화면 이탈은 onPause가 아니다.** 진단 목적지를 떠나면 진행 중 지원 조회·STT·수동 마이크·수동 UWB를 명시적으로 정리하도록 검증한다. `cancelTeslaKey`의 정확한 `serviceOwned` 제외는 유지하되 수동 작업이나 음성/프렁크에 background 예외를 확대하지 않는다.
- 화면 이동·회전·재구성으로 probe를 중복 생성하거나 자동으로 시험을 다시 시작하지 않는다. 정리 실패 때 오디오 예약을 풀어 성공으로 숨기지 않는다.
- 음성 프렁크는 마이크 해제뿐 아니라 인식기/pipe 정리 확인까지 모두 충족한 뒤에만 dispatch·음성 lease 반환·차량 core 입장을 허용한다. 인식 성공과 정리 실패가 함께 온 결과는 정리 불명으로 차단하고 기존 예약·재입장 차단을 유지한다. 명령 문법/n-best·점수 미제공·신선 P·단발 actuator·ACK/후속 BODY/물리 완료의 경계는 그대로다.
- 사용자가 명시적으로 등록한 VIN은 AndroidKeyStore로 보호하는 앱 전용 암호화 저장소에 영구 보관하고, 앱 재실행·휴대폰 재부팅 후 차량 키 등록·인증·P 조회·BLE 감지에서 공통 재사용할 수 있다. 평문 저장·복호화 실패 시 평문 fallback·로그/Wiki/저장소 기록·Android 백업·기기 간 전송은 금지한다. 기본 표시는 마스킹하고 편집 중 입력은 RAM에서만 취급하며 화면 이탈 시 지운다. VIN 등록·변경·복원만으로 차량 작업·감지·마이크를 자동 시작하지 않는다. 서비스 복원은 별도 저장 ON·새 token/빈 후보·새 광고 계약을 따른다. 실행 중 VIN 변경을 막고 각 작업은 시작 시 확정한 대상 VIN을 끝까지 사용한다. 기존 앱 키·차량 등록·설정·로그와 `FLAG_SECURE`는 유지한다.
- 설정은 기존 시스템 권한 launcher/설정/차량 chooser로 연결한다. 설정·권한·기본 비서를 사용자 대신 승인하지 않는다.

## 완료 판정

- 실제 구현한 홈/설정/진단 경로를 실행한다. 첫 진입, 설정 미완료, 권한 거절, 처리 중, 취소, 실패, 재진입을 해당 범위에서 확인한다.
- 화면 전환·HOME·회전 뒤 마이크/인식/FD/예약이 남지 않는지 검사한다. UI 재배치 후에도 기존 무음 TTS 양성·무음 PCM 대조·취소 경로를 사용한다. 일반 사용자의 발화 참여는 마지막 물리 검증에만 요청한다.
- 작은 화면, 시스템 글자 확대, 긴 한국어 상태에서 겹침·핵심 문구 잘림을 확인한다. 터치 목표는 최소 48dp, 일반 텍스트 대비는 4.5:1, 의미 있는 비문자 컨트롤은 3:1 이상을 지킨다. TalkBack 레이블과 뒤로 가기 순서를 확인한다.
- 기본 글자 크기 첫 화면에서 대상·현재 상태·다음 행동의 위치를 확인한다. 큰 글자에서는 한 화면 수용보다 내용 보존과 스크롤 접근을 우선한다. 상세를 열지 않고도 실패 여부와 중지 방법을 알 수 있어야 한다.
- 홈 → 설정 → 진단 → 뒤로 경로를 실제로 조작하고, 접힌 상세를 열어 기존 근거가 남아 있는지 확인한다. 설치 성공·컴파일 성공만으로 정보 위계와 조작 검증을 대신하지 않는다.
- 스크린샷이 보안 정책으로 차단되면 이를 유지하고 UI 계층·실제 조작·상태로 확인한다. 이 경우 **픽셀 기반 시각 검증 미완료**라고 보고한다. 의미 계층 검사만으로 미적 완성을 주장하지 않는다.
- 새 테스트는 상태 오표시·게이트 우회·화면 이탈 누수처럼 실제 회귀를 막는 경우에만 추가한다. 문구·소스 텍스트·필드 전달을 고정하는 테스트는 만들지 않는다.
- 최종 보고: 변경 화면, 유지한 안전 계약, 실제 검증, 미확인 범위. 위키의 실측과 계획을 구분한다.
