# 18단계 구현 계획과 승인 경계

[Wiki 홈](Home.md) · [루트 README](../README.md) · [기기 검증](Device-Validation.md) · [상태 머신](State-Machine.md) · [Tesla 연동](Tesla-Integration.md)

> 2026-09-30 기준 진행 기록이다. 최신 `0.8.0-probe`는 마이크와 분리된 접근 관찰 FGS를 구현하고 S23의 시작·HOME·짧은 화면 꺼짐 유지·앱/알림 종료·프로세스 재생성 OFF를 확인했다. 실제 잠금·주머니 차량 접근·장기 대기·감지 지연은 미검증이다. 기존 7단계의 합성 문장 일치는 실제 발화·신뢰도 합격을 뜻하지 않는다.

## 운영 원칙과 현재 범위

- **현재 완료한 개발 범위는 접근 관찰 전용 포그라운드 서비스와 수명주기 검증**이다. 기존 UI·7단계 STT/PCM·제한 마이크의 안전 조건을 보존한다. 다음 물리 검증은 새 버전의 잠금·주머니 접근·이탈과 장기 대기이며, 6단계 최종 합격은 여전히 대기다.
- 6단계 미통과는 독립적인 음성 조사·개발까지 금지하는 조건이 아니다. 실제 접근에 연결한 음성 처리의 최종 합격에는 여전히 6단계 실기기 증거가 필요하다. 8단계 이후 연속 발화·명령 처리는 이번 범위 밖이다.
- [UI 개편 순서](UI-Design.md#점진적-개편-순서)의 화면 책임 분리·테마·홈·진단 UX는 코드에 반영했다. 실제 기기 확인 범위와 남은 회귀는 [실측 기록](Device-Validation.md)에 구분한다. 현재 기능·권한·수명주기를 유지하고 미구현 기능을 꾸민 성공 화면으로 채우지 않는다. 이 트랙은 아래 원래 18단계의 대체물이 아니다.
- 기본 실행은 mock/dry-run이다. USB 없이 조사·코드·호스트 빌드는 가능하며 대상 기기의 지원 조회·음성 API·설치는 연결 시 실측한다. 수동 STT는 화면 표시 중에만 허용하고 기존 접근·마이크 세션과 상호 배제한다. ADB 권한 우회, 상시 녹음, 실차 제어, LLM은 도입하지 않는다.
- **사용자 참여를 최소화한다.** 파일 생성·직접 PCM 주입·무음 대조·취소·설치·결과 수집을 먼저 자동화한다. 사무실에서 직접 말하거나 스피커를 재생하도록 요구하지 않는다. 실제 발화·음향·차량 접근처럼 대체할 수 없는 물리 조건만 별도로 남기며, 합성 시험을 그 증거로 승격하지 않는다.
- **승인 경계**는 사용자의 명시적 참여가 필요한 지점이다. 기본 비서 변경·런타임 권한 승인·실제 걸어서 접근하는 시험, 비용·계정·키·실차 명령은 승인 없이 진행하지 않는다.
- 차량 접근 신호는 차량 제어 권한이나 사용자 인증의 증거가 아니다. 불확실성·실패는 성공으로 대체하지 않고 기록한다.

## 단계별 계획

### 1단계 — 개발 환경·기기 조건

- **세부 작업:** Android 16/API 36 시험 기기와 Android Studio bundled Java 21.0.10, AGP 9.3.1, Gradle 9.5.0, SDK 36을 프로젝트의 호환 후보로 기록한다. Kotlin·Compose 버전은 AGP와 실제 프로젝트 템플릿의 호환 범위에서 선택한다. `ANDROID_HOME`과 오래된 `ANDROID_SDK_ROOT`의 충돌은 개인 절대 경로를 문서화하지 않고 프로젝트 로컬에서 해소한다.
- **통과 기준:** 유효한 SDK 36과 Build Tools 36.0.0을 해석하는 프로젝트 설정과 실행 가능한 Gradle wrapper가 있다. One UI는 설정 화면 확인 전 `80500` 외의 버전 표기를 확정하지 않는다.
- **선행 의존성:** 없음.
- **승인 경계:** 없음. USB 연결·설정 화면 관찰에 사용자 조작이 필요하면 그 관찰만 사용자 참여로 수행한다.

### 2단계 — 단일 Kotlin + Compose 프로젝트와 dry-run

- **세부 작업:** 단일 `app` 모듈 Kotlin + Compose 프로젝트를 만들고, Tesla 인증·명령·서버 없이 Gradle wrapper와 Android SDK 설정을 연결한다. 진단 앱의 기본 실행 경로만 둔다.
- **통과 기준:** 메인이 실제 `:app:assembleDebug`를 실행해 APK를 생성하고 대상 기기에 설치한다. 구성 해석이나 Gradle `--dry-run`만으로 통과 처리하지 않는다. 설치 성공과 잠금·접근 동작 성공은 별도로 기록한다.
- **선행 의존성:** 1단계의 호환 조합과 SDK 경로 해소.
- **승인 경계:** 없음.

### 3단계 — 초기 설정·진단 화면·비민감 로그

- **세부 작업:** 최소 Compose 화면으로 현재 설정·권한·접근 세션·오디오 상태와 dry-run 여부를 드러낸다. 로그는 `sessionId`, 상태, 이벤트, 경과 시간, 성공 여부, 정해진 오류 코드와 필요한 비민감 측정값으로 제한한다.
- **통과 기준:** 설치된 앱의 실제 화면에서 권한·서비스·세션 상태와 dry-run 표시를 확인한다. 원본 음성, 차량·Bluetooth 식별자, 계정·토큰·키, 개인명·일련번호·로컬 절대경로는 진단 로그에 저장하거나 표시하지 않는다. 구현 범위 밖인 호출어·STT와 미검증 상태를 명확히 표시한다.
- **선행 의존성:** 2단계의 실행 가능한 앱 골격.
- **승인 경계:** 실제 권한 요청이나 기본 비서 변경은 5단계에서 사용자 승인 후에만 한다.

### 4단계 — 실제 Tesla BLE 접근·이탈·재연결 조사

- **세부 작업:** 실제 차량 접근·이탈, 차량 수면·탑승 전후, Bluetooth 재연결과 다른 Tesla 차량이 있는 조건에서 후보 신호를 관찰한다. 목표 차량을 구분할 수 있는지, debounce·cooldown에 필요한 사건이 무엇인지 조사한다.
- **통과 기준:** 실제 접근에서만 후보 대기 조건이 시작·재개되는지, 이탈과 재연결이 중복 세션을 만들지 않는지, 다른 차량을 목표 차량으로 오인하지 않는지를 기록한다. 구분 가능한 신호가 없으면 실패로 기록하고 후속 세션을 시작하지 않는다.
- **선행 의존성:** 3단계의 비민감 진단 경로와 실제 차량.
- **승인 경계:** 실제 차량 근처 접근 시험은 사용자 참여가 필요하다. BLE 접근 관찰은 Tesla 제어·키 인증·GATT 직접 제어 권한이 아니다.

### 5단계 — VoiceInteractionService·microphone FGS·AudioRecord 제한 세션

- **세부 작업:** 사용자가 선택한 `VoiceInteractionService` 경로에서만, 접근 조건을 만족한 한정 세션에 microphone foreground service와 `AudioRecord`를 시작하는 후보를 구현한다. 완료·이탈·취소·오류·만료마다 캡처, STT, TTS, 포커스, 작업, 버퍼를 해제한다.
- **통과 기준:** 원거리에서 마이크·STT 활성 시간은 0이어야 하며, 세션당 캡처 소유자는 하나다. `AudioRecord`의 stop/release와 관련 자원 해제가 모든 종료 경로에서 관찰된다. 서비스가 생성되었다는 로그나 캡처 API 성공만으로 유효한 입력·호출어 인식을 주장하지 않는다.
- **선행 의존성:** 4단계 접근 후보와 3단계 진단 로그.
- **승인 경계:** 기본 비서 변경과 `RECORD_AUDIO` 등 실제 권한은 사용자 승인을 받고, 기존 비서 영향과 해제 방법을 고지한 뒤에만 수행한다.

### 6단계 — 잠금·주머니·실제 접근 무터치 시험

- **세부 작업:** 초기 설정 후 휴대전화를 잠가 주머니에 넣고, 차량 밖에서 실제로 걸어서 접근한다. 앱 실행, 알림 터치, 잠금 해제, 마이크 버튼, 매사용 서비스 수동 시작 없이 제한 세션의 시작·종료를 관찰한다.
- **통과 기준:** 실제 접근만으로 세션이 시작 또는 재개되고, 이탈·취소·오류에는 오디오 자원이 해제된다. 매사용 화면 조작이나 ADB 특권에 의존한 성공은 불합격이다. 호출어와 STT는 7단계 이후이므로, 이 단계의 마이크 캡처는 호출어 인식 성공이 아니다.
- **선행 의존성:** 5단계 제한 세션, 4단계의 목표 차량 구분.
- **승인 경계:** 잠금·주머니·실제 접근 시험은 사용자가 참여한다. 이 단계는 실차 제어를 포함하지 않는다.

### 7단계 — 온디바이스 한국어 호출어·STT 선정

- **세부 작업:** 후보 호출어 엔진과 STT의 `ko-KR` 모델, 라이선스, 비용, 네트워크 전송 여부, 오프라인 동작, 외부 PCM 입력 지원을 비교한다. Android 온디바이스 인식 지원 여부와 실제 모델 설치 상태를 확인한다.
- **통과 기준:** 선택안이 오프라인 한국어 처리·라이선스·비용·모델 배포 조건을 충족한다고 문서와 실기기로 각각 확인한다. 지원하지 않거나 신뢰도 값이 낮거나 없으면 실행을 거절하며, 승인 없는 클라우드 fallback은 없다.
- **선행 의존성:** 후보 조사와 지원 조회 구현은 기존 제한 세션과 독립적으로 진행할 수 있다. 사용자는 6단계 실측을 보류하고 이 작업을 먼저 진행하도록 승인했다. 최종 선택의 실기기 합격과 실제 접근 통합에는 6단계 오디오 경로 및 한국어 발화·외부 PCM 실측이 필요하다.
- **승인 경계:** 비용, 외부 SDK, 오디오 외부 전송은 사용자 사전 승인이 필요하다.

### 8단계 — 연속 발화와 첫 음절 보존

- **세부 작업:** “헤이 테슬라 프렁크 열어줘”를 멈추지 않고 말하는 경로에서 호출어 감지와 명령 STT를 연결한다. 필요한 경우 접근 세션 안에서만 짧은 RAM 버퍼의 인계를 검토한다.
- **통과 기준:** 실제 연속 발화에서 명령 첫 음절을 잃지 않은 최종 인식을 확인한다. 실패하면 원인을 기록하고 이 게이트는 미통과로 남긴다. 원거리 선행 수집·상시 녹음·저장 오디오는 사용하지 않는다.
- **선행 의존성:** 7단계 선택과 6단계 실제 제한 세션.
- **승인 경계:** 없음. 외부 음성 처리로 바꾸려면 7단계 승인 경계를 다시 적용한다.

### 9단계 — 허용 문법 파서

- **세부 작업:** 허용된 단일 명령만 구조적으로 해석하고, 부정·취소·회상·모호한 참조와 낮거나 없는 신뢰도를 안전하게 거절한다. 부분 인식 결과로 명령을 전송하지 않는다.
- **통과 기준:** “프렁크 열지 마”, “아까 열어달라고 했잖아”, 모호한 “문 열어줘”는 실행 후보가 되지 않는다. 최종 결과가 없거나 신뢰도를 신뢰할 수 없으면 거절·종료한다.
- **선행 의존성:** 8단계 최종 발화 결과 형식.
- **승인 경계:** 없음.

### 10단계 — 전체 상태 머신과 회귀 시험

- **세부 작업:** 단일 세션, monotonic 만료, 중복 억제, 취소, cooldown, 늦은 결과의 무효화와 `UNKNOWN` 결과를 상태 머신에 반영한다. 파서·상태 전이의 경계 시나리오를 회귀 시험한다.
- **통과 기준:** 중복 전송, 만료된 명령 실행, 취소된 명령의 나중 실행, 결과 불명 자동 재전송이 없다. 모든 종료 경로가 오디오·작업을 해제한다. 단위 시험은 OS 권한·실제 마이크 동작의 증거로 쓰지 않는다.
- **선행 의존성:** 9단계 명령 결과와 기존 [상태 머신 계약](State-Machine.md).
- **승인 경계:** 없음.

### 11단계 — 실제 발화 → dry-run → TTS → 해제 통합

- **세부 작업:** 실제 발화 결과를 파서와 상태 머신에 연결하고, `VehicleGateway`의 dry-run 경계로만 전달한다. TTS 결과 안내 뒤 입력과 출력 자원을 끝낸다.
- **통과 기준:** 허용 명령만 dry-run 결과를 얻고, 취소·오류·만료·실패는 실행으로 가장하지 않는다. TTS가 자기 재인식 루프를 만들지 않고, 완료 뒤 모든 오디오 자원이 해제된다.
- **선행 의존성:** 8~10단계.
- **승인 경계:** 없음. dry-run은 실차 요청의 숨은 fallback이 아니다.

### 12단계 — Fleet API 계정·지역·비용·도메인·서버 검토

- **세부 작업:** 실제 계정의 Fleet API 지원 지역·권한·비용·결제 조건, 도메인·서버 필요성을 확인하고 공식 Go `vehicle-command`의 명령 서명 경로를 검토한다. 기존 데이터 경로로 충분한지 먼저 판단한다.
- **통과 기준:** 계정·지역·비용·도메인·서버·공식 서명 구성요소 각각의 필요 여부와 미확인 사항이 분리되어 있다. Node.js + TypeScript 서버는 필요성이 확인된 뒤에만 고려하며 독자 서명 구현은 하지 않는다.
- **선행 의존성:** 11단계 dry-run 통합과 [Tesla 연동 문서](Tesla-Integration.md).
- **승인 경계:** 계정 연결, 비용 발생, 도메인·서버 운영은 사용자 명시적 승인이 필요하다.

### 13단계 — OAuth·가상 키·토큰 보관·철회

- **세부 작업:** 필요한 OAuth 범위, 앱 공개키 등록, 토큰·키의 분리 보관, 갱신·철회·유출 대응 절차를 설계·구현한다.
- **통과 기준:** 토큰·키·계정 식별자를 코드, 로그, Wiki에 기록하지 않는다. 권한 철회와 키 폐기 경로가 있으며, Tesla 공식 앱 폰키를 앱 명령 권한으로 오해하지 않는다.
- **선행 의존성:** 12단계 실제 연동 전제 확인.
- **승인 경계:** OAuth 승인, 가상 키 등록, 토큰 발급·보관은 사용자 명시적 승인이 필요하다.

### 14단계 — 명령 없는 읽기 진단과 신선한 명시적 P

- **세부 작업:** 명령을 보내지 않는 읽기 진단으로 인증·권한·차량 상태 경로와 관측 시각을 확인한다. `P`는 명시적·유효·신선한 값만 통과시키고 `null`, `Unknown`, `Invalid`, `SNA`, 속도 0은 안전한 P로 취급하지 않는다.
- **통과 기준:** 실제 명령 없이 상태 획득 가능 여부와 상태 신선성 정책을 기록한다. 유효한 명시적 P를 얻지 못하면 다음 단계의 명령을 막는다.
- **선행 의존성:** 13단계 인증·키 경로.
- **승인 경계:** 실제 계정·차량 읽기 진단은 사용자의 명시적 승인이 필요하다.

### 15단계 — 개별 승인 실차 프렁크 시험과 음성 결합

- **세부 작업:** 먼저 수동 진단 경로에서 한 번의 프렁크 요청을 시험하고, 요청 수락·래치 해제·후드 완전 개방·결과 불명을 구분한다. 통과한 안전 경로만 음성 흐름에 결합한다.
- **통과 기준:** 사용자가 대상 차량과 명령 효과를 확인한 개별 승인 아래, 신선한 명시적 P·미만료 의도·중복 없음·네트워크 정책을 만족할 때만 요청한다. 결과 불명은 `UNKNOWN`으로 알리고 자동 재전송이나 완료형 TTS를 하지 않는다.
- **선행 의존성:** 14단계 읽기 진단, 10~11단계 안전한 음성 경로.
- **승인 경계:** **각 실차 프렁크 시험 전에 사용자 명시적 승인**이 필요하다. 승인 전 실차 제어는 금지다.

### 16단계 — 소음·통화·마이크 경합·네트워크·차량 수면 실패 시험

- **세부 작업:** 바람·옷 마찰·차량 소음, 통화, 다른 앱의 마이크 점유·무음 입력, 네트워크 단절, 차량 수면을 실제 조건에서 시험한다.
- **통과 기준:** 유효 입력과 정책상 무음을 구분하고, 실패·거절·대기·결과 불명을 정확히 기록한다. 마이크를 강제로 점유하거나 안전 조건을 완화하지 않는다.
- **선행 의존성:** 15단계 승인된 명령 경로 또는 명령 없는 동등 실패 경로.
- **승인 경계:** 실차 상태를 유발하거나 명령을 포함하는 경우 15단계의 개별 승인을 적용한다.

### 17단계 — USB 분리 장기 대기·배터리·종료·재부팅·업데이트

- **세부 작업:** USB를 분리한 상태에서 원거리 장기 대기와 배터리를 측정하고, 일반 프로세스 종료, 최근 앱 제거, 재부팅 전후, 앱 업데이트를 각각 시험한다.
- **통과 기준:** 원거리 대기에서 마이크·STT 활성 시간은 0이며, 환경·기간·시도·성공·실패·복구 범위를 함께 기록한다. 사용자 강제 중지 뒤 자동 복구는 보장하지 않으며, 이를 우회하지 않는다.
- **선행 의존성:** 16단계 실패 처리와 실제 대기 경로.
- **승인 경계:** 장기 측정과 기기 설정 변경·재부팅은 사용자 참여가 필요할 수 있다. 강제 중지 자동복구 보장은 요구하지 않는다.

### 18단계 — 개인용 APK·설정·해제·검증 범위 정리

- **세부 작업:** 실제로 검증한 개인용 APK의 설치·초기 설정·권한·기본 비서 해제·계정 및 키 철회 절차와 검증 범위를 정리한다.
- **통과 기준:** 문서는 확인한 빌드·설치·실기기 결과만 주장하고, 미검증 조건과 비목표를 함께 밝힌다. 개인 식별 정보, 차량 식별자, 음성 원문, 토큰·키, 로컬 절대경로는 포함하지 않는다.
- **선행 의존성:** 1~17단계에서 실제로 확보한 검증 증거.
- **승인 경계:** 배포·설정 변경·실제 계정·키 철회는 사용자 승인 범위에서만 수행한다.

| 게이트 | 통과 전 금지 | 통과 근거 |
| --- | --- | --- |

| 7~11 | 실제 Tesla 요청 | 온디바이스 한국어·연속 발화·파서·상태 머신·dry-run 종료 기록 |

| 16~18 | 강제 중지 우회·미검증 APK 홍보 | 실패·장기 대기·복구·설치의 실제 증거 |
