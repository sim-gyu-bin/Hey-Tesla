# UI 검토와 프로젝트 디자인 스킬

[Wiki 홈](Home.md) · [제품 요구사항](Requirements.md) · [구현 계획](Implementation-Plan.md) · [프로젝트 UI 스킬](../.omp/skills/hey-tesla-ui/SKILL.md)

> 2026-09-22 UI 개편과 2026-09-29 스킬 강화·적용 기록. 진단 문서를 화면에 옮긴 듯한 UI를 개선하기 위해 Tesla 공식 공개 화면의 정보 위계를 참고했다. **`0.5.0-probe` 빌드·Lint, S23 설치와 홈·설정·진단 지원 조회를 확인했다.** 음성 회귀·큰 글꼴·TalkBack·픽셀 검증은 미완료이며 세부 한계는 [실측 기록](Device-Validation.md)에 남긴다.

## 결론

색상만 바꾸는 개편으로는 부족하다. **진단 순서대로 나열한 화면을 사용자 목적별 화면으로 바꾸는 것**이 먼저다. Tesla의 기능·브랜드를 복제하지 않고 차량 중심 정보 계층, 짧은 상태, 여백, 주요 행동과 상세 메뉴의 분리를 차용한다.

적용한 구조는 **홈 → 설정 → 개발자 진단**이다. 기존 시험 기능을 없애지 않는다. 홈은 사용자 상태와 다음 행동, 설정은 초기 준비, 개발자 진단은 시험과 측정 근거를 맡는다. 운영 목표인 잠금·주머니 무터치를 매사용 버튼 조작으로 대체하지 않는다.

## 현재 화면의 문제와 소스 근거

아래 분석과 행 번호는 **개편 전 `0.4.0-probe`의 `MainActivity.kt`**를 기준으로 보존한 기록이다. 실제 화면이 문서처럼 느껴진다는 사용자 관찰을 전제로 원인을 분석했다. 현재 구현은 `ui/`로 분리되어 있으므로 이 행 번호를 새 코드 위치로 해석하지 않는다. `FLAG_SECURE`는 유지한다.

| 문제 | 소스 근거 | 개편 판단 |
| --- | --- | --- |
| 사용자 목적 대신 시험 순서 | `MainActivity.kt:79–174`, 단일 세로 스크롤의 번호 섹션 1~7 | 홈/설정/진단으로 분리 |
| 첫 화면에 구현 제약과 긴 설명 | `80–82`, `89–95`, `105–112` | 간결한 개발용 표시와 현재 행동에 필요한 경고만 근처에 유지 |
| 원시 값이 핵심 상태보다 앞섬 | `85`, `98`, `109`, `115`, `168–174` | 홈은 사용자 언어, 기술 코드·수치는 진단 상세 |
| 모든 버튼이 같은 강조 | `86–94`, `100–111`, 이후 진단 버튼 | 주 행동 하나, 설정 행, 시험 동작, 중지/취소 위계 구분 |
| 제품 시각 기준 없음 | `77–80`: 기본 `MaterialTheme`, 외곽 20dp, 균일 간격 12dp | 프로젝트 테마·타이포·간격 기준을 한곳에서 관리 |

공통으로 어두운 저채도 배경, 밝은 주요 텍스트, 회색 보조 정보, 넓은 여백, 대상 중심 시각 요소가 보인다. 빠른 조작과 세부 목적지를 구분하며 모든 정보를 카드와 문단으로 동일하게 나열하지 않는다.

**근거의 한계:** 스토어 이미지의 촬영 앱 버전은 확인되지 않았다. 최신 Tesla 앱의 정확한 화면·폰트·색상·전환 규격으로 단정하지 않는다. 한국어 소개 URL은 reader에서 403, 브라우저에서는 404였고 공식 지원 URL은 접근 거부였다. 이 두 페이지의 내용은 분석 근거로 사용하지 않았다. 차량 렌더링·로고·공식 스크린샷을 저장소나 앱 에셋에 복사하지 않았다.

## 제안하는 첫 화면

아래는 **설정 미완료 상태의 정보 배치 예시**이며 실행 가능한 앱이나 실제 연결 상태 표시가 아니다.

```text
Hey Tesla                              설정
개발용 · 차량 제어 미연결

Model Y
차량 등록이 필요해요

[허가된 차량 시각 요소가 있을 때만 배치]

차량 근처에서 사용할 준비를 시작하세요
[ 차량 등록하기 ]

준비 상태
차량 등록             필요
권한                  확인 필요
음성 기능             개발 검증 중
```

- 첫 화면에서 상태와 다음 행동을 찾을 수 있게 한다. 등록 완료 후에도 호출어·실차 제어가 없으면 `사용 준비 완료`로 승격하지 않는다.
- 설정은 홈 상단에서 진입한다. 개발자 진단은 설정의 명시적 항목으로 제공하고 숨은 제스처로 감추지 않는다.
- 차량 그림은 필수가 아니다. 적법한 에셋이 없으면 실제 정보와 여백으로 구성한다. 시연용 배터리·P·연결·프렁크 상태를 꾸며 넣지 않는다.
- 기존 접근 진단 스위치를 예쁜 홈 토글로 바꾸는 것만으로 제품이 완성되는 것은 아니다. 처음에는 진단에 그대로 유지한다.

## 프로젝트 스킬

파일은 **`.omp/skills/hey-tesla-ui/SKILL.md`**, 이름은 **`hey-tesla-ui`**다. 사용자 전역 스킬은 변경하지 않는다. 새 세션에서 프로젝트 스킬로 발견되며, 현재 세션에서 아직 발견되지 않았다면 파일 경로로 읽어 적용한다. 사용자의 세션을 임의로 재시작하지 않는다.

스킬에는 정보 구조, 실제 상태와 허용 문구, 초기 색상·간격·타이포, Compose 수명주기, 승인·개인정보 경계, 실제 UI 검증 기준을 담았다. 색상/간격은 Tesla 추출값이 아니며, 현재 구현한 색상·타이포의 단일 원본은 `app/src/main/java/com/heytesla/app/ui/AppTheme.kt`다.

호출 예: `hey-tesla-ui 스킬로 홈과 개발자 진단을 분리해 줘.` 명시 호출이 활성화된 세션에서는 `/skill:hey-tesla-ui`를 사용할 수 있다.

## 점진적 개편 순서

아래 순서의 **1~4는 `0.5.0-probe` 코드에 반영했으며 5는 일부 확인**했다. 설치와 홈·설정·지원 조회 관찰을 전체 회귀 합격으로 확대하지 않으며 기존 18단계의 실차·음성 합격 기준도 바꾸지 않는다.

1. **화면 책임 분리:** 현재 동작을 유지하며 홈·설정·개발자 진단으로 이동한다. 시험 버튼·로그·안전 설명의 목적지를 보존한다. 같은 Activity 안에서 진단 화면을 떠날 때도 진행 중 수동 시험과 지원 조회를 정리한다.
2. **테마와 공통 표현 적용:** 프로젝트 토큰, 설정 행, 상태 요약, 주 행동·중지/취소 위계를 적용한다. 기존 토큰/컴포넌트와 병렬 체계를 만들지 않는다.
3. **홈 완성:** 실제 상태에서 파생한 짧은 요약과 다음 행동, 적법한 차량 시각 요소를 구성한다. 아직 없는 기능은 버튼·수치로 위장하지 않는다.
4. **진단 UX 정리:** 시험 선택 → 실행/취소 → 결과 요약 → 상세 근거의 흐름으로 바꾼다. 긴 설명을 접더라도 권한·기본 비서 대체·시험 조건 경고는 해당 행동 가까이에 남긴다.
5. **실제 화면 검증:** 설정 미완료·오류·처리 중·이탈·재진입, 글자 확대·좁은 화면·TalkBack을 확인한다. 기존 무음 TTS 양성·무음 대조·취소로 기능 회귀를 확인한다. 보안으로 픽셀 검증이 불가능하면 그 한계를 명시한다.

마이크 권한·오디오 예약·화면 표시·접근 OFF·단일 세션 게이트를 유지한다. UI 이동 중 재녹음·중복 probe·늦은 콜백·예약 조기 해제를 막는다. 사용자 참여는 자동화로 대체할 수 없는 실제 음향·차량 접근 검증에서만 요청한다.

실제 홈은 별도 차량 이미지나 임시 도식 대신 `Model Y` 제목과 대상 차종·개발 중 표시를 사용한다. 밝은 중립 CTA, 차콜 배경, 중립 설정 아이콘을 적용했다. 진단 입력은 합성 음성·무음 대조를 먼저 두고 상세 메타데이터·원시 수치는 펼쳐 보게 했다. 설정 행의 Button 역할, 제목 heading, 진단 탭의 선택·밑줄, 입력의 단일 선택 의미를 제공하지만 실제 TalkBack·글자 확대 검증은 아직 하지 않았다.

## 문서·스킬과 구현 검증

- 프로젝트 루트에서 `omp read skill://hey-tesla-ui:1-12`를 실행해 로컬 스킬의 발견·읽기를 확인했다. 사용자 전역 설정과 실행 중인 메인 세션은 변경하지 않았다.
- README·Wiki·스킬의 내부 링크와 기존 구현 계획의 1~18단계를 검증한다. 새 화면 경로는 README와 아키텍처에 반영하며 이전 실측은 버전별 이력으로 유지한다.
- 실제 테마의 불투명 문자 색상 12조합은 최소 6.45:1로 계산됐다. 스킬 작성 때의 초기 팔레트 12조합(최소 6.86:1)과 대상 조합이 다르다. 두 계산 모두 실제 화면·비활성/투명도·다른 배경의 검증을 대신하지 않는다.
