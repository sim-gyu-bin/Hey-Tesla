# UI 검토와 프로젝트 디자인 스킬

[Wiki 홈](Home.md) · [제품 요구사항](Requirements.md) · [구현 계획](Implementation-Plan.md) · [프로젝트 UI 스킬](../.omp/skills/hey-tesla-ui/SKILL.md)

> 현재 소스·생성 APK·S23 설치본은 `0.66.0`/66·서비스 OFF·실제 서비스 실행0이다. 별도 출처의 좌표 기반 대략적 거리/폰 상단 기준 화살표와 기존 UWB를 병행한다. 실제 홈 OFF·설정 버전·선택 위치 권한 안내와 합성 입력의 Compose 만료/OFF 경계를 확인했다. 자동 마이크·프렁크는 미연결이며 실제 차량 위치·UWB 수신·방향 정확도는 미검증이다. [v66 정본](Tesla-Integration.md#v66-좌표-기반-나침반uwb-병행)과 [실측 기록](Device-Validation.md)을 따른다. 큰 글꼴·TalkBack·보안 본문 픽셀 검증은 미완료다.

## 결론

색상만 바꾸는 개편으로는 부족하다. **진단 순서대로 나열한 화면을 사용자 목적별 화면으로 바꾸는 것**이 먼저다. Tesla의 기능·브랜드를 복제하지 않고 차량 중심 정보 계층, 짧은 상태, 여백, 주요 행동과 상세 메뉴의 분리를 차용한다.

적용한 구조는 **홈 → 설정 → 개발자 진단**이다. 홈은 서비스 사용과 실제 감지·자동 UWB 상태, 설정은 초기 준비, 개발자 진단은 남은 시험과 측정 근거를 맡는다. 사용자 요청으로 차량 감지·BLE 비교·접근 관찰 시험 UI는 제거했으며, 음성·수동 마이크·수동 UWB·차량 키·이벤트는 유지한다. 운영 목표인 잠금·주머니 무터치를 매사용 버튼 조작으로 대체하지 않는다.

## 서비스 사용 중심 홈

- 주 조작은 **서비스 사용 ON/OFF**다. `bleDetectionEnabled`는 저장된 사용 의도이고, 시작·중지·감시·스캔 복구·차량 신호·오류는 실제 runtime 상태에서 표시한다. 저장 ON을 정상 실행으로 위장하지 않는다.
- v55의 제품 모드 `VEHICLE_SERVICE_UWB`는 **사용자 서비스 ON → 신선한 정확 BLE 광고 → 기존 앱 키 인증·FiRa 협상 → 자동 UWB 측정 → 알림**이다. 과거/별도 `VEHICLE_NAME_DETECTION`의 감지 전용 계약과 구분한다. 자동 마이크·호출어·프렁크는 미연결이며 마이크·기본 비서 준비 여부를 서비스 시작 조건으로 쓰지 않는다.
- 저장 ON 복원은 새 token·빈 후보로 감지를 시작하고 이후 새 광고만 소비한다. 이전 후보·인증·UWB 세션·측정값·명령은 재생하지 않는다. OFF와 알림 중지는 영속화하며 시작 실패·권한 상실에도 OFF 조작을 허용한다. OS가 복원을 거절하면 제한 사유와 직접 시작 필요를 표시한다.
- `RANGING` 미허용은 BLE 감지를 유지한 채 UWB만 차단한다. 권한은 설정의 명시적 행동과 기존 시스템 launcher로 요청하며 자동 승인하지 않는다. 권한 결과·팝업 복귀만으로 종료된 서비스를 다시 시작하거나 이전 측정을 재생하지 않는다.
- 홈·설정의 주말 BLE 시험 제목·회차 조작·시험 로그 문구는 현재 제품 표현에서 제거했다. 과거 검증 로그·스키마는 역사적 근거로 보존한다. 기존 데이터·키·차량 등록과 남은 수동 진단의 취소·화면 이탈 정리는 유지한다.
- 스위치는 라벨을 포함한 행 전체를 조작 영역으로 사용한다. 실제 Android 접근성 트리의 라벨과 상태 보유 토글 관계를 따라 checked/enabled·OFF 동작을 검증하며 특정 내부 노드 배치를 고정하지 않는다.
- [v0.53 기기 기록](Device-Validation.md#0530-probe--홈-서비스-제어와-감지만-복원)은 당시 감지 전용 홈과 보안 화면의 픽셀 검증 한계에 대한 이력이며 v55 자동 UWB의 기기 검증 근거가 아니다.

### v66 좌표 기반 대략적 안내

- [좌표·권한·수집 수명 정본](Tesla-Integration.md#v66-좌표-기반-나침반uwb-병행)을 따른다. 홈/알림에서 좌표 기반 대략적 거리·방향과 UWB 최근 거리/AoA 검증 상태를 별도 출처로 표시한다. 폰 상단 기준 화살표를 UWB 정밀360도·차량 전후·탑승·제어 허가로 표현하지 않는다. 원시 좌표는 표시/로그/영속 상태에 넣지 않고 RAM 전용 source에서 좌표 없는 presentation만 받는다.
- 차량60초·폰15초·heading2초를 독립 만료한다. heading만 오래되면 화살표만, fix가 만료/부정확하면 거리/방향을 숨긴다. 근처 `max(10m, accuracy)`는 방향 없음,1km 초과는 거리만이다. 미수신을0m/0도·정면으로 만들거나 UWB 각도를 섞지 않는다. 숫자 없이도 대기·권한·오래됨·센서 불명·시계 샘플 지연/무효·정리 실패와 다음 행동을 알 수 있게 한다.
- 설정의 **항상 위치 허용(선택)**은 Android 앱 설정으로 연결하고 사용자 직접 승인만 허용한다. visible/unlocked에서 시작한 FGS의 HOME·잠금 유지에는 이 선택 권한이 필수가 아니다. background 권한 없는 boot/복원은 BLE/UWB 유지·좌표 명시 앱 재개로 설명하며 권한 결과만으로 죽은 서비스를 재시작하지 않는다.
- **서비스 ON/FGS armed = GPS 상시 수집**으로 설명하지 않는다. 동일 새 접근 request에서만 phone source를 시작하고 좌표 거절/timeout/무결과 종료에는 해제한다. 유효 차량 fix가 있어도 원 나이를 반영한60초 이내 남은 기간까지만 유지하고 source 종료 때 raw RAM을 지운다. 자동 마이크·프렁크 미연결과 기존 ON/OFF·정리 실패 우선 표시는 유지한다.


## 설정의 설치 버전 표시

- **설정 → 앱 정보 → 앱 버전**에 현재 APK의 버전 이름과 빌드 번호를 표시한다. `BuildConfig.VERSION_NAME`·`VERSION_CODE`를 사용하며 화면에 번호를 별도로 하드코딩하지 않는다.
- 기존 `DetailRow`를 재사용하는 읽기 전용 정보다. 시스템 앱 설정 버튼은 유지하고 권한·서비스·진단을 시작하지 않는다.
- **v63 기기 관측:** 데이터 보존 설치 후 package `0.63.0`/63과 실제 설정의 `0.63.0 (빌드 63)`을 대조했다. 차량 시스템 등록·권한 모두 허용 표시·홈 OFF를 확인하고 서비스를 켜지 않은 채 홈으로 복귀했다. 보안 잠금·`FLAG_SECURE`는 유지하며 픽셀 기반 시각 검증은 수행하지 않았다.
- **v55 기기 관측:** 데이터 보존 설치 뒤 실제 설정 UI에서 `0.55.0 (빌드 55)`와 권한 허용 상태를 확인했다. 홈 ON, HOME에서 서비스 알림 유지, 알림의 **서비스 끄기**, 재진입 OFF를 확인했다. 상세 근거와 한계는 [v55 기기 기록](Device-Validation.md#0550--자동-uwb-서비스와-알림)에 둔다.
- **v54 역사적 기기 기록:** `0.54.0-probe (빌드 54)`의 생성된 BuildConfig JVM 실행값·APK 메타데이터를 대조했고, 데이터 보존 설치 후 실제 설정 진입과 버전 표시를 접근성 UI 계층으로 확인했다. 이 관측을 v55 표시·기기 검증 성공으로 옮기지 않는다. 글꼴 확대·TalkBack·픽셀 기반 시각 검증은 아직 하지 않았다.


## 컬러 차량 앱 아이콘

- 기존 시스템 마이크 아이콘을 모델 Y의 둥근 크로스오버 비율·가로 조명에서 착안한 자체 차량 일러스트로 교체했다. v58은 사용자 요청에 따라 빨간 차체를 스텔스 그레이 계열의 짙은 메탈릭 회색으로 바꿨다. 짙은 유리·청록 그라데이션 배경·차량 형태는 유지하며 테슬라 T 심볼·공식 앱 아이콘·외부 차량 이미지는 사용하지 않는다. 이는 화면용 자체 팔레트이며 실제 도장색의 측색값을 재현했다는 뜻은 아니다.
- `@mipmap/ic_launcher` adaptive icon을 일반·원형 앱 아이콘에 공통 적용한다. 차량 전경·배경을 분리하고 중앙 안전 영역을 사용한다. 테마 단색 아이콘은 기존 자체 차량 실루엣을 여백과 함께 재사용한다. 상태바 아이콘은 컬러 앱 아이콘과 별도다.
- v57은 S23 런처·시스템 앱 정보에서 컬러 차량 렌더링을, v58은 시스템 앱 정보의 실제 픽셀 캡처에서 그레이 차체를 확인했다. 기기에 별도 아이콘 테마가 적용된 상태이며 화면에 보이는 종이 모양 외곽 프레임은 앱 에셋에 없다. 사용자 테마 설정은 변경하지 않았다. 단색 테마·다른 런처 마스크는 실기 검증하지 않았다.

## 서비스 자동 UWB와 알림

- 상태바·서비스 알림에는 자체 제작한 24dp 단색 차량 정면 벡터 `ic_vehicle_notification`을 사용한다. 테슬라 T 심볼·공식 앱 아이콘은 쓰지 않는다. 제품 서비스와 BLE 감지의 기본 알림은 같은 리소스를 사용하며, 별도 마이크 진단의 마이크 아이콘은 유지한다. v56 S23 상태바 캡처에서 실제 차량 모양 렌더링을 확인했다.

- HOME·잠금·진단 화면 이탈에서 유지되는 측정은 살아 있는 서비스 owner·token·현재 회차·VIN에 귀속한 정확한 `serviceOwned` 경로뿐이다. 수동 등록·조회·UWB의 화면/잠금 게이트를 일반적으로 완화하지 않는다.
- 한 접근 후보당 한 번 측정하며 스캔 pause·GATT·정리 시간을 이탈로 세지 않는다. 서비스 측정은 최초 유효 거리 대기 60초, 유효 수신 뒤 10초 미수신으로 종료한다. 유효 수신 중에는 기존 고정 60초·전체 180초로 끊지 않지만 초기 연결·인증·협상 기한은 유지한다. 이 값은 종료 정책이지 수신·근접 보장이 아니다.
- OFF·권한·BT·owner 상실은 새 전송을 봉인하고 정리한다. native 정리 실패는 예약과 FGS를 유지하고 재입장을 막으며 정상 중지로 표시하지 않는다. wake lock은 대기 중 없고 초기 185초, 이후 새 유효 거리 수신 때만 최소 5초 간격의 20초 유한 갱신이며 완료·정리 실패에도 해제를 시도한다. 해제 자체가 불명이면 lock 참조·실패 상태·field/scan 예약·FGS를 유지하고 재시작 필요를 표시한다.
- 알림은 `serviceOwned`의 `RANGING` 단계에서 살아 있는 peer의 callback 수신 elapsed 기준 최근 2초 이내 유효 거리만 `UWB 최근 거리 … m · peer N`으로 표시한다. 최신 callback을 선택하고 동시 수신이면 작은 peer index를 선택하며, 최단 거리 선택이나 다른 peer의 각도 혼합은 하지 않는다. peer 정지·endpoint close·정리 즉시 현재값에서 제외하고 과거 표본은 진단 근거로만 보존한다.
- callback이 없어도 기존 readiness 갱신에서 2초 표시 TTL 만료를 반영한다. 미수신·지연·중지·실패를 구분하고 전체 중지/정리 실패 및 UWB 오류가 거리보다 우선한다. 이 TTL은 세션의 10초 미수신 종료와 별개다.
- AoA는 실제 이번 세션 capability에 따라 요청한다. v59의 동일 표본 raw 각도·독립 confidence·축별 지원 로그와 당시 화살표 보류 이력은 유지한다. 설치 모듈 radians·공개 API degrees의 충돌과 단위 식별 부재로 **UWB 기반 화살표**는 검증 중이며 변환/기기명·해시 추정을 하지 않는다. v66의 별도 WGS 좌표·폰 진북 안내는 이 AoA를 사용하거나 합성하지 않는다.

## UWB 지원과 별도 수동 거리 진단

- 개발자 진단의 UWB 탭 안에서 **수동 차량 UWB 거리 진단**과 **사전 지원 조회**를 분리한다. 서비스 OFF·기존 앱 키·명시적 `RANGING` 권한·직접 시작은 수동 경로의 조건이며 제품 서비스의 자동 측정에 OFF를 요구하지 않는다. 시작/정지·차단/종료 사유는 상세 밖에 둔다.
- 세션 열림·peer 시작을 실제 거리 수신 성공으로 표시하지 않는다. 미수신은0m가 아니며 실제 peer별 m·confidence·유효/무효 횟수를 표시한다. 종료 후 마지막 값은 과거 결과로 구분하고 자동 거리/제어 조건에 쓰지 않는다.
- framework 원시 시각과 callback 수신 elapsed, `onOpenFailed`와 `onClosed` 원 코드를 상세에서 분리한다. 화면 결과는 RAM, 비민감 거리·raw 각도·독립 confidence·축별 지원 여부는 기존 순환 로그에 남기고 VIN·주소·STS는 표시/기록하지 않는다.
- 수동 진단은 버튼만 실행 capability를 전달하며 화면 진입·권한 승인 결과·재구성·프로세스 복원으로 측정을 자동 시작하지 않는다. 기존 측정 60초·전체 180초 제한과 화면 이탈·HOME·잠금 취소를 유지한다. 정리 불명 경고/예약은 Activity 재생성으로 숨기지 않는다.
- v54 수동 UWB의 당시 근거는 호스트 빌드·프로토콜/CLI smoke다. 위 v54 설치·앱 버전 표시 관측은 수동 UWB의 실제 UI·HOME/잠금·실차 거리·native 종료 검증과 별개다.

### v59 방향각 검증 안내

- v59에서 추가한 UWB 진단의 **360° 방향 검증 단계**는 **UWB AoA 기반** 회전 화살표 미표시·동일 표본 raw 로그 저장을 설명한다. 현재 v66 좌표 화살표와 다른 검증이다. 상세에는 정차 차량 앞에서 폰을 세로로 세워 후면을 차량 쪽으로 향한 뒤, 몸과 폰을 함께 오른쪽 한 바퀴 돌며90°마다5초 멈추는 당시 절차를 둔다.
- 실제 기기에서 새 안내·미수신 상태·허용된 RANGING과 설정 버전 표시를 확인했다. 값이 없을 때 0°나 정면으로 표시하지 않으며 시험 절차를 통과했다고 360도 방향 정확도 성공으로 승격하지 않는다. 알림·자동 UWB 수명과 기존 서비스 ON 설정은 유지한다.


### v55 소스·호스트 관측과 기기 검증의 경계

- 현재 소스 계약과 별도로 메인이 앱/androidTest/JVM 빌드 및 실제 컴파일 클래스의 JShell 합성 smoke를 수행했다. 정확한 `FILTERED_SCAN`만 시작·CDM/자체 BT 무시·OFF 봉인·유효 거리 300초 지속과 10초 미수신 종료·수동 60초·1.25m 알림과 2초 만료·정지 peer 제외·정리 우선은 합성 입력의 관측이다.
- 최종 유한 wake-lock 수정 포함 빌드·JVM404개·분석기105개·Lint 오류0을 확인했고, S23의 UI/런타임 자동 검증39개와 실제 서비스 알림 ON/OFF·설정 버전 표시를 확인했다. 이는 BLE/UWB RF, 실제 거리·방향, 측정 중 잠금 지속, native 정리의 실기기 합격이 아니다. `FLAG_SECURE`로 앱 픽셀 검증은 제한되며 큰 글꼴·TalkBack은 미검증이다.

## 과거 BLE 대조 조건 UI

BLE 연결 탭은 **기준 방식 / 개선 방식** 프리셋과 **감지만 · GATT 없음 / 필터 BLE 스캔 / BT 연결 신호 보조 / 백그라운드 연결 / 제한 재시도**를 분리한다. 기준이 기본이며 개선 선택도 `autoConnect=true`를 자동 선택하지 않는다. 조건은 시작 전 RAM 선택·실행 중 고정이고 권한 요청/승인은 시작과 별개다. SCAN 미승인을 사용할 수 있는 상태처럼 표시하지 않는다.

근접 후보·GATT 회차/완료·스캔 실행/실패와 실행·정리 상태를 구분한다. 본시험/정리 SDK status와 첫 RX는 증거 상세에 두며 null/0 RX를 실패나 성공으로 임의 승격하지 않는다. 지속 알림과 화면의 중지 행동을 유지하고 `FLAG_SECURE`를 해제하지 않는다. 추가 테마나 병렬 상태 모델은 만들지 않는다.


## 차량 키 조회 결과 표시

`0.19.0-probe`는 기존 probe 상태를 그대로 사용해 화면 상단과 조회 버튼 바로 아래에 큰 결과 문구를 표시한다. 진행·정리는 파랑, 검증된 암호 상태 조회 성공은 초록, 실패·시간 초과·시작 불가·정리 실패는 빨강, 취소는 노랑이다. 색뿐 아니라 문구로 구분하고 실패 근거는 상세를 열지 않아도 보인다.

종료 시 더 기다릴 필요가 없음을 명시한다. 결과 불명은 성공으로 바꾸지 않으며 정리 실패는 검증된 응답보다 우선한다. 등록 보고만으로 조회 성공을 표시하지 않는다. 프로토콜·기한·재시도·차량 조작과 등록 승인 경계는 변경하지 않는다.

`0.20.0-probe`는 설정에 **차량에 앱 키 등록**을 추가한다. 시스템 차량 등록과 별개임을 표시하고 VIN·명시적 동의·시작·차량 키카드 승인으로 이어진다. 기존 실제 등록 구현을 공유하며 읽기 전용 조회는 개발자 진단에 유지한다. 기술 표는 상세로 옮기고 승인 대기·앱 키 확인·종료 결과를 행동 근처에도 표시한다. 등록 보고 뒤 인증 실패는 등록 보고 수신과 앱 키 확인 실패를 따로 알린다. 뒤로·홈·HOME 이탈은 기존 취소 경로를 사용하며 VIN과 동의를 비우고 자동 재개하지 않는다.

## 실차 음성 시험 진행 표시

`0.46.0-probe`는 실차 시험 영역에서 실제 관측 단계에 따라 음성 인식·오디오 해제·차량 연결/인증·신선한 P 확인·명령 전송·차량 응답·열림 보고를 구분한다. 시간 경과로 진행률이나 성공을 만들지 않는다. 종료 시 마지막 관측 단계와 사유를 남기며 정리 실패·취소와 전송 후 철회 불가 경고를 유지한다.

최대40초는 기존 차량 작업 기한이며 고정 대기 시간이 아니다. ACK를 열림이나 물리 완료로 표시하지 않는다. 상세를 펼치지 않아도 현재 진행·실패와 취소 행동을 확인할 수 있게 한다. 실제 기기 검증 범위는 [실측 기록](Device-Validation.md)에 구분한다.

실차 음성 시험 동의는 프렁크 1회 동작과 마스킹 인식 로그 저장을 고지하며 기본 OFF·세션 RAM 유지·시작 후 해제다. v49부터 별도 녹음 저장 동의 체크는 없으며, 직접 시작한 개발용 마이크 시험의 녹음·최종 인식 원문은 앱 내부 백업 제외 저장소에 기본 보관한다. 시작 버튼 근처에 기본 저장을 안내하고 수동 시작 버튼을 유지하며, 화면 진입·복원·복귀만으로 녹음하지 않는다. 추가 확인 발화는 없다. 녹음은 ADB로 회수하고 휴대폰 엔진에 다시 입력할 수 있으나 재시험은 차량 제어 경로와 연결하지 않는다. 외부 업로드·자동 삭제는 하지 않는다.

v0.51부터 일반 음성 시험 결과 요약과 실차 음성 시험 상세에 n-best 원문을 `후보 N` 행으로 최대 3개 표시한다. 각 행에는 점수(0.0 등은 `점수 미제공(원값)`)를 붙이고, 후보가 더 많으면 전체 개수를, 실차 시험에는 `인식 판정`(명령 문장 인정 · 차량 실행 허가 아님 / 차단 · 사유)을 함께 둔다. 바로 아래에 RAM 전용·다음 같은 시험 시작·프로세스 종료 시 지움·주변 대화 표시 가능·차량 실행 허가 아님을 안내한다. 사용자 취소 회차는 표시하지 않으며, FLAG_SECURE로 화면 캡처는 막힌다.

v0.52부터 음성 인식 진단 결과에 "실험용 로컬 인식(sherpa-onnx)" 섹션과 "차량 제어·명령 판정에 사용 안 함" 안내를 둔다. 인식 텍스트, 기대 문장 일치/불일치, 명령 판정 라벨, `모델 로드 N ms · 인식 N ms`, 실패 코드(`SHADOW_MODEL_MISSING`/`SHADOW_LOAD_FAILED`/`SHADOW_DECODE_FAILED`)를 표시한다. 그림자 원문도 v0.51 후보와 같은 RAM 전용 규칙을 따르며 사용자 취소 회차에는 표시하지 않는다. 실차 음성 시험 영역에는 표시하지 않는다.

**근거의 한계:** 스토어 이미지의 촬영 앱 버전은 확인되지 않았다. 최신 Tesla 앱의 정확한 화면·폰트·색상·전환 규격으로 단정하지 않는다. 한국어 소개 URL은 reader에서 403, 브라우저에서는 404였고 공식 지원 URL은 접근 거부였다. 이 두 페이지의 내용은 분석 근거로 사용하지 않았다. 차량 렌더링·로고·공식 스크린샷을 저장소나 앱 에셋에 복사하지 않았다.

## 제안하는 첫 화면

아래는 **설정 미완료 상태의 정보 배치 예시**이며 실행 가능한 앱이나 실제 연결 상태 표시가 아니다.

```text
Hey Tesla                              설정
개발용 · 차량 제어 미연결

Model Y
차량 등록이 필요해요

[허가된 차량 시각 요소가 있을 때만 배치]

차량 근처에서 사용할 준비를 시작하세요
[ 차량 등록하기 ]

준비 상태
차량 등록             필요
권한                  확인 필요
음성 기능             개발 검증 중
```

- 첫 화면에서 상태와 다음 행동을 찾을 수 있게 한다. 등록 완료 후에도 호출어·실차 제어가 없으면 `사용 준비 완료`로 승격하지 않는다.
- 설정은 홈 상단에서 진입한다. 개발자 진단은 설정의 명시적 항목으로 제공하고 숨은 제스처로 감추지 않는다.
- 차량 그림은 필수가 아니다. 적법한 에셋이 없으면 실제 정보와 여백으로 구성한다. 시연용 배터리·P·연결·프렁크 상태를 꾸며 넣지 않는다.
- 기존 접근 진단 스위치를 예쁜 홈 토글로 바꾸는 것만으로 제품이 완성되는 것은 아니다. 현재 제품 토글은 별도 `VEHICLE_SERVICE_UWB` 경로이며 과거 BLE/접근 진단 조작을 홈에 되살리지 않는다.

## 프로젝트 스킬

파일은 **`.omp/skills/hey-tesla-ui/SKILL.md`**, 이름은 **`hey-tesla-ui`**다. 사용자 전역 스킬은 변경하지 않는다. 새 세션에서 프로젝트 스킬로 발견되며, 현재 세션에서 아직 발견되지 않았다면 파일 경로로 읽어 적용한다. 사용자의 세션을 임의로 재시작하지 않는다.

스킬에는 정보 구조, 실제 상태와 허용 문구, 초기 색상·간격·타이포, Compose 수명주기, 승인·개인정보 경계, 실제 UI 검증 기준을 담았다. 색상/간격은 Tesla 추출값이 아니며, 현재 구현한 색상·타이포의 단일 원본은 `app/src/main/java/com/heytesla/app/ui/AppTheme.kt`다.

호출 예: `hey-tesla-ui 스킬로 홈과 개발자 진단을 분리해 줘.` 명시 호출이 활성화된 세션에서는 `/skill:hey-tesla-ui`를 사용할 수 있다.

## 점진적 개편 순서

아래 순서의 **1~4는 `0.5.0-probe` 코드에 반영했으며 5는 일부 확인**했다. 설치와 홈·설정·지원 조회 관찰을 전체 회귀 합격으로 확대하지 않으며 기존 18단계의 실차·음성 합격 기준도 바꾸지 않는다.

1. **화면 책임 분리:** 현재 동작을 유지하며 홈·설정·개발자 진단으로 이동한다. 시험 버튼·로그·안전 설명의 목적지를 보존한다. 같은 Activity 안에서 진단 화면을 떠날 때도 진행 중 수동 시험과 지원 조회를 정리한다.
2. **테마와 공통 표현 적용:** 프로젝트 토큰, 설정 행, 상태 요약, 주 행동·중지/취소 위계를 적용한다. 기존 토큰/컴포넌트와 병렬 체계를 만들지 않는다.
3. **홈 완성:** 실제 상태에서 파생한 짧은 요약과 다음 행동, 적법한 차량 시각 요소를 구성한다. 아직 없는 기능은 버튼·수치로 위장하지 않는다.
4. **진단 UX 정리:** 시험 선택 → 실행/취소 → 결과 요약 → 상세 근거의 흐름으로 바꾼다. 긴 설명을 접더라도 권한·기본 비서 대체·시험 조건 경고는 해당 행동 가까이에 남긴다.
5. **실제 화면 검증:** 설정 미완료·오류·처리 중·이탈·재진입, 글자 확대·좁은 화면·TalkBack을 확인한다. 기존 무음 TTS 양성·무음 대조·취소로 기능 회귀를 확인한다. 보안으로 픽셀 검증이 불가능하면 그 한계를 명시한다.

마이크 권한·오디오 예약·화면 표시·접근 OFF·단일 세션 게이트를 유지한다. UI 이동 중 재녹음·중복 probe·늦은 콜백·예약 조기 해제를 막는다. 사용자 참여는 자동화로 대체할 수 없는 실제 음향·차량 접근 검증에서만 요청한다.

실제 홈은 별도 차량 이미지나 임시 도식 대신 `Model Y` 제목과 대상 차종·개발 중 표시를 사용한다. 밝은 중립 CTA, 차콜 배경, 중립 설정 아이콘을 적용했다. 진단 입력은 합성 음성·무음 대조를 먼저 두고 상세 메타데이터·원시 수치는 펼쳐 보게 했다. 설정 행의 Button 역할, 제목 heading, 진단 탭의 선택·밑줄, 입력의 단일 선택 의미를 제공하지만 실제 TalkBack·글자 확대 검증은 아직 하지 않았다.

## 2026-09-29 스킬 강화와 화면 적용

- 스킬에 **대상 → 상태 → 주 행동 → 상세** 구성 계약, 화면별 첫 뷰포트 기준, 좋은 예·나쁜 예, 설치 버전 확인, 실패·중지·승인 경계를 접지 않는 검수 기준을 추가했다.
- 홈은 카드 겹침을 없애고 `Model Y`, 실제 준비 상태, 주 행동 하나의 크기·간격으로 위계를 표현한다. 가짜 차량 상태나 이미지는 추가하지 않았다.
